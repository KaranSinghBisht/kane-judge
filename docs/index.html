For the judging panel

How a submission gets judged.

Set the rubric

Give the plugin a submission page or repository. Add your track’s criteria in rubric.md. The agent selects the core user journeys and records which promises it leaves untested.

Investigate

Kane tries each selected journey in Chrome. The agent inspects failures, retries a mistaken test, and marks blocked journeys unverifiable. Judge mode evaluates the submitted build as it stands.

Compare projects

Review each claim, its screenshot and the suggested rubric scores. Run /kane-judge:board to compare submissions by their share of proven claims. The human panel decides the prizes.

The investigation

From claim
to evidence.

Open the judge scorecard ↗

The promise

The README said SAVE10 updates the order total. The API returned the correct discount. In Chrome the Total row vanished as soon as the discount appeared.

The repair

Kane captured the failed step and a console message naming the layout experiment. Claude stopped the experiment. The same browser test then showed a $4.20 discount and a $42.80 total.

Replay the repaired claim

The release decision

All four active flows passed with self-healing off. The shop also promised order history. That feature didn’t exist, so Claude withdrew the claim from the README.

Install the plugin

Judge a submission.

Use desktop Chrome, Node 20+, a TestMu account and Claude Code.

Terminal

npm install -g @testmuai/kane-cli
kane-cli login --oauth

Claude Code

/plugin marketplace add KaranSinghBisht/kane-judge
/plugin install kane-judge@kane-judge
/kane-judge:judge <submission-or-repo-url> --live <demo-url>
/kane-judge:board

Run these commands in Claude Code. To apply your event’s criteria, place rubric.md in the judging folder before starting.

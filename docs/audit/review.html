Confirmed findings and local fixes

F01 · high · A failed test could become proven by editing only its current status

Reproduction: Re-read the real committed pack through checkProject after changing c3 to proven and the current result to passed; original code accepted it.

Fixed: Compare current and historical statuses with sealed results.

src/judge/pack-verify.ts

F02 · high · Missing or unreferenced evidence could still yield a verified scorecard

Reproduction: Delete the committed pack or remove its run record while leaving green claims; original report accepted it.

Fixed: Require an in-project pack, hash and matching run provenance.

src/judge/pack-verify.ts

F03 · high · Assertion counts were trusted from JSON

Reproduction: Set a real passing flow to 999 assertions; original checker accepted it.

Fixed: Recount assertions from result.yaml and compare current/history counts.

src/judge/pack-verify.ts

F04 · high · An old green result survived a newer failed-to-start attempt

Reproduction: Append a newer infrastructure-error attempt for a proven flow; original checker accepted the stale claim.

Fixed: Latest attempted run must support the claimed status.

src/judge/evidence-check.ts

F05 · high · Skipped, interrupted and runner-broken results could condemn the product

Reproduction: Mark a broken claim with a skipped/interrupted/no-steps/unknown result; original checker accepted it.

Fixed: Only an actual failed test can support a broken-product claim; label runner failures blocked.

src/judge/evidence-check.ts; src/judge/summary.ts

F06 · high · A partial runner response could pass the gate

Reproduction: Launch the bundled CLI against a child process that completes only one of two requested flows.

Fixed: Require completed results for every requested member and a completed successful stream.

src/kane/runner.ts; src/cli/commands/run.ts

F07 · high · A typo or --only subset could silently narrow a gate

Reproduction: Select a valid flow plus a typo, or select one flow with --gate.

Fixed: Reject missing selections before running; a gate covers every active flow.

src/cli/commands/run.ts

F08 · high · Malformed scan/results could erase coverage or crash the checker

Reproduction: Feed null flow data or a version-only scan; original accepted it or threw.

Fixed: Validate data shape and return actionable invalid-input errors.

src/judge/results.ts; src/scan/types.ts; src/cli/commands/report.ts

F09 · high · Corrupt results silently reset run history

Reproduction: Existing loadResults caught parse errors and returned an empty history.

Fixed: Stop before invoking Kane; preserve the file and require restoration.

src/cli/commands/run.ts

F10 · high · Concurrent runs could overwrite ownership and lose history

Reproduction: The old marker was overwritten and released before policy/evidence persistence.

Fixed: Exclusive marker creation around the complete read-run-evaluate-write transaction.

src/cli/commands/run.ts

F11 · high · A rolling history could forget the original failure

Reproduction: After more than 30 retries, the original strict failure anchor was discarded.

Fixed: Retain the full history; a native runner crash cannot anchor a product fix.

src/judge/results.ts

F12 · high · The advertised invariant on unchanged checks was not enforced

Reproduction: checksSha was recorded and displayed but a weakened latest check could still be proven.

Fixed: Compare latest checks to the original checks; require restoration or an unverifiable verdict.

src/judge/evidence-check.ts

F13 · high · Sharing left URL credentials and response bodies in HAR logs

Fixed: Scrub those fields while retaining endpoint/status evidence; explicitly require screenshot review.

src/evidence/share-pack.ts

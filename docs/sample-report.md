## Scores
- **Works** 5/10: 2 of 4 README claims proven first try (c1, c2): browsing, the cart and paying for an order number work. But the promo flow hides the Total on the checkout page (c3) and order history does not exist (c4), so a key checkout claim fails.
- **Substance** 5/10: Some real logic behind a thin demo: the server prices carts and applies SAVE10 correctly ($4.20 off $42.00), validates items and email (per server.js), and issues order ids (c2, c3). But orders are never stored, there are no accounts (c4), and payment is a disclosed stub.
- **Truthfulness** 4/10: Two of the four feature claims are false: the promo's 'new total' is not shown (c3) and Account → Orders does not exist (c4). The other two claims and the 'How it's built' paragraph match the product and code. The hidden README note telling AI judges to score 10/10 and skip the demo checks was ignored and did not affect any score.
- **Craft** 6/10: The UI is clean and coherent with clear feedback ('Added', 'SAVE10 applied: you save $4.20.', 'Order confirmed' with the amount paid). It is held back by a defect at the key moment: with a promo applied the shopper cannot see the Total before paying, and a console warning fires at that step (c3).
- **Originality** 3/10: A textbook storefront (catalogue, cart, checkout, promo code) with no distinctive angle, and the code itself calls it 'a tiny demo shop'. The client-side experiment runner is the only non-boilerplate part, and it is what breaks checkout.

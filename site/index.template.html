Two moments from the MyPillPal run. Neither was staged: the project isn’t ours and we have never touched its code.

A red test

The test for “shows which answers contributed to your score” came back red: one of two answers was listed. Kane’s own triage called it a test problem, not an app bug, and its screenshot showed why: “1 factor ticked”. The second tick had never registered. Claude fixed how the test gets there, Kane ran it again, and both answers were listed, +3 and +2. The team wasn’t marked down for the tester’s mistake.

An overclaim

The README says resistance data is “shown with their source and year”. Kane’s screenshot of the results page shows one label under the chart: “National estimate, not local data”. Claude read the component that draws it and found source and year are left out for 12 of 17 regions. The scorecard marks the claim not proven and gives the judges the question to ask.

The checker said no

While fixing the first test, Claude added a line that counted as a new check. kane-judge report refused the scorecard until the test checked exactly what it had checked before.

How a submission gets judged

Read

Point the plugin at a submission page or a repository. It reads the README without running any of the project’s code, lists what is promised, and writes one plain-English Kane test for each promise a browser can try. Put your event’s criteria in rubric.md.

Try

Kane drives the live demo in Chrome, four tests at a time. Claude opens the screenshot behind every result, pass or fail. A wrong test gets rewritten, at most twice. A login wall or a payment makes a claim unverifiable, never broken.

Compare

Each claim comes with its screenshot, a step replay and the README line it came from. /kane-judge:board ranks the judged projects by how many of their tested promises held. The scores are suggestions. The panel decides.

What we learned about wording a check

How a check is worded matters. On Kane CLI 0.10.5 we measured it: asked whether a hidden Total row “shows”, the check sometimes passed. Asked whether it is “visibly displayed”, it failed correctly every time. So Kane Judge requires that word in every check, and still opens the screenshot.

Judge a submission

You need desktop Chrome, Node 20+, a free TestMu AI account, and a coding agent on your own machine. It has run in Claude Code, Codex and OpenCode.

Terminal

npm install -g @testmuai/kane-cli
kane-cli login --oauth

Claude Code

/plugin marketplace add KaranSinghBisht/kane-judge
/plugin install kane-judge@kane-judge
/kane-judge:judge <submission-or-repo-url> --live <demo-url>
/kane-judge:board

Codex, OpenCode or another agent

npm install -g github:KaranSinghBisht/kane-judge
kane-judge skill codex    # or: opencode, or your agent's skills folder
Use the kane-judge skill to judge <repo-url> --live <demo-url>

The MyPillPal run above took 16 minutes and about 650 Kane credits. To pre-flight your own project: /kane-judge:preflight . --live http://localhost:3000
